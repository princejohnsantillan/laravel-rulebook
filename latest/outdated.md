# Outdated patterns (not included as rules)

**Version:** 2026-10-13 18:19. Practices that are outdated for Laravel 13, kept here with citations for reference.

- (Infra / Queues & workers) Run independent I/O concurrently (e.g. `Concurrency`, Octane tasks); don't expect it to parallelize CPU work. — The blanket claim that Concurrency or Octane tasks cannot parallelize CPU work is incorrect. Laravel 13 Concurrency uses separate PHP processes with its process and fork drivers, and Octane's Swoole concurrent tasks use separate task workers; independent CPU work can run in parallel when CPU capacity is available. See https://laravel.com/framework/docs/concurrency and https://laravel.com/framework/docs/octane#concurrent-tasks. — sources: [Laravel (official)](https://laravel.com/docs/13.x/octane) (Official, 3); [Mateus Guimarães](https://www.youtube.com/watch?v=dOXXL-98Zbs) (Laracon speaker, 2)
- (Codebase / Validation & security) Use Gate::after to override earlier authorization decisions or enforce non-bypassable administrator constraints — Laravel 13 after-hook return values cannot override a non-null allow or deny, so mandatory constraints belong in the decision path
- (Infra / Scaling, Octane & performance) Use HTTP/2 server push to send anticipated page resources before the browser requests them, with preload Link headers informing server push — Chrome disabled HTTP/2 server push by default in version 106 and Nginx made its push directives obsolete; use preload or Early Hints instead
- (Codebase / Architecture & structure) Register middleware and console schedules in Kernel classes and locate rate-limit configuration in a RouteServiceProvider or HTTP Kernel. — This is legacy skeleton guidance, not the Laravel 13 default: streamlined applications configure middleware in bootstrap/app.php, schedules in routes/console.php or withSchedule(), and rate limiters in an application service provider. — sources: [Laravel (official)](https://github.com/laravel/boost/tree/main/.ai) (Official, 3)
- (Codebase / Design patterns & code style) Use the project formatter and a current agreed PHP coding standard consistently. — PSR-2 is superseded by PSR-12; do not introduce PSR-2 as a separate current requirement. — sources: [Laravel (official)](https://github.com/laravel/pint/blob/main/resources/presets/laravel.php) (Official, 3); [Sam Sehnert](https://www.youtube.com/watch?v=IPbxscS0xiY) (Laracon speaker, 2); [Spatie](https://spatie.be/guidelines/php) (Tier 2, 2)
